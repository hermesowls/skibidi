# Lossless large-file storage

Hermes skill_manage enforces 20 operations per atomic batch and 1 MiB / 100,000 characters per supporting file. This helper uses 80,000-character shards. Large logical files (source YAML, resolved JSON inventory and some category references) are stored as ordered `.partNNN` UTF-8 chunks plus `<logical-path>.index.json`. The index contains every part path, exact byte count and SHA-256. Concatenate listed parts without separators to recover the COMPLETE file. No truncation or summarization occurs. `scripts/refresh_docs.py` exports `load_logical(path)` and uses it during validation. If a referenced logical path does not exist, read its `.index.json` and parts instead. Generated catalog links refer to logical paths; these may require this reconstruction rather than a direct Markdown viewer. Supporting-file batches are atomic individually, not across the entire refresh; always run final offline validation before claiming completeness. No dependency on caches or temporary files.

For direct endpoint inspection through `terminal`, run `python ~/.hermes/skills/financial/unusual-whales-api/scripts/refresh_docs.py --show-operation 'GET /api/option-trades'`. This reads only durable local artifacts and prints that full resolved operation; choose exact keys from catalog.md. Offline `--validate` independently compares source operation keys with inventory and catalog, checks complete regenerated files and hashes, and validates request template parameters. It does not send any template request.

Bulk application uses the installed `tools.skill_manager_tool.skill_manage(..., operations=...)` Python entry point in atomic batches of at most 20. This is the same skill manager, not direct repository/file writes. Only `--apply-public-refresh` needs that installed Hermes module; offline validation and payload generation use stdlib plus PyYAML.
