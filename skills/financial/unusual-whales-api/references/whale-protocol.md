# Whale evidence protocol

## User defaults and non-negotiable distinctions
Premium >= $50,000; individual trade **size >= 500 contracts**; contract volume > open interest; DTE 1 through 14 inclusive as of the **current analysis date in America/New_York**; OTM with **UNLIMITED OTM DISTANCE** (`max_otm_fraction: null`, local policy only, never an invented API parameter). These are user screening defaults, not a prediction or proof of informed buying. Size is not cumulative contract volume or a count of prints. Never replace the size threshold with `min_volume=500`. Unlimited OTM distance is not a statement about a premium cap. Premium strings need decimal-safe parsing and documented currency/contract multiplier; retain source premium rather than reconstructing when supplied.

Maintain separate views:
1. **Raw threshold candidate:** source row matches observable thresholds. Missing inputs are unknown, not zero/false. Keep provider-asserted predicates separate from independently recomputed predicates.
2. **High-premium aggregated whale order/activity:** `include_agg_trades=true` explicitly rolls related transactions together and applies size/premium filters to the combined row. Alert premium is also aggregated. Do not describe a $50k roll-up as a $50k single print or assert one beneficial owner.
3. **Verified individual print:** individual transaction provenance/ID, execution time, price, size and constituent status establish one execution. A request with `include_agg_trades=false` is request evidence, not a substitute for examining row fields and source semantics. Do not claim a verified print when aggregation status remains unknown.
4. **Ask-side/buyer-initiated inference:** contemporaneous executable NBBO, timestamp alignment, actual fill price and trade conditions support an inference only. A string `ASK` tag != an ask fill; aggregate ask percentage != every constituent hitting ask. Crossed/locked/stale markets and delayed reports weaken classification.
5. **Confirmed buy/open:** requires evidence not normally provided by public tape (participant/order-side/open-close context). Every execution has a buyer and seller. Do not call public-flow heuristics confirmed buys or opening positions.

## Exact endpoint differences
Approved default: `GET /api/option-trades` with exactly `{"min_premium":"50000","min_size":500,"volume_greater_oi":true,"min_dte":1,"max_dte":14,"is_otm":true,"include_agg_trades":false,"limit":20}`. The endpoint maximum is 500, not the approved request limit. Nonaggregated selection still requires row-level evidence checks. Aggregated examples are a separately authorized, different cohort, never the default or a silent replacement.
Alerts `/api/option-trades/flow-alerts`: `vol_greater_oi` (not tape spelling), integer `min_premium`, max `limit=200`. Alerts are rule-based aggregates. A generic `min_volume=500` alert example is not the baseline: cumulative volume >=500 proves neither individual size >=500 nor 500 prints. The documented `/api/option-trades/flow-alerts/{id}` describes associated trades (including related multi-leg trades), but `trades.items` is only an untyped object schema. Examples do not establish guaranteed print fields, verified individual executions or complete constituent retrieval. Inspect actual rows, `has_more`, and documented `older_than` pagination; do not claim completeness from this route alone. Neither alert count nor aggregated rows are single-print counts.

## Evidence checks
- Preserve original row, request parameters, endpoint, retrieval time, source execution time, provider ID, pagination progress and any response date. Hash raw evidence if required; redact authorization only.
- Use decimal-safe money and explicit null/absent handling. Distinguish absent key, null, false and zero.
- Baseline DTE is expiry date minus the current analysis date in America/New_York (calendar days, 1–14 inclusive); record that analysis date and expiry convention explicitly. Historical source-execution-date DTE may be reported only as a separate source-only diagnostic, never substituted for baseline DTE. Provider filtering is not proof of this local date basis. Do not fabricate source execution timestamps from retrieval time, alert time or today's date.
- OTM calls require strike > contemporaneous spot; puts strike < spot. Equality is ATM. Validate compact contract identifiers before extracting expiry/type/strike; do not repair malformed symbols silently. Index weekly symbols such as SPXW may need an explicitly evidenced underlying mapping; never substitute an unrelated price or infer spot from strike.
- Compare execution versus time-aligned bid/ask and report absolute/relative spread with its denominator. No hard spread threshold is imposed by the user defaults. Missing bid/ask means unknown, not a tight spread.
- Compare IV on like-for-like contracts/horizon/moneyness and time; distinguish decimal IV from percentage display. Distinguish IV change from IV level, rank and percentile; do not compare unmatched expiries as evidence of a volatility signal.
- Identify multi-leg/spread/stock-linked activity, sweeps, corrections/cancellations and aggregation. A purchased call can be a hedge or a spread leg; net strategy direction differs from leg direction.
- Volume > OI does not prove opening: volume is cumulative turnover and OI is an outstanding-position snapshot. Next-session OI change can corroborate net positioning only; it cannot attribute openings to this print. Save when that OI became available and never leak it into a point-in-time screen/backtest.

## Known evidence pitfall and baseline diagnostics
A saved-response prior-project report reviewed during the skill work reported 20 rows lacking `is_agg` and null SPXW underlying spot. This is report-level provenance, not fresh market retrieval, a fresh row-level re-test, or evidence supplied directly by the user. Absence of `is_agg` MUST remain unknown, never `false`; null spot leaves recomputed OTM unknown. Do not fabricate a timestamp or fill missing spot with today's quote.

Before changing filters, retain baseline request, unmodified raw rows, unique-row count and separate pass/fail/unknown counts per threshold: premium, individual size, volume-vs-OI, analysis-date DTE, OTM (unlimited distance), aggregation, timestamp and optional directional confidence. Preserve raw-threshold matches even when stricter single-print or directional verification is unavailable; report those downstream exclusions separately. Retain exact reason codes such as `missing_is_agg`, `null_underlying_price`, `missing_execution_timestamp`, `premium_below_min`, `size_below_min`, `volume_not_gt_oi`, `dte_outside_range`, `otm_unknown`, without pretending these are provider fields. Never modify a user's ingestion pipeline merely by loading this skill.

Report total candidates with deduplication basis, aggregate candidates, verified prints, unknown aggregation, missing spot and incomplete pagination. No fake example market rows; request templates are not observations.
