# Finviz bounded operator recovery

Existing research CLI supports `research recovery-status`, `research migrate-ledger`, and `research release-rate-limit` with `--provider finviz --root EXPLICIT --cohort TEST|REAL_DATA_RESEARCH --authorize-research`. These commands only inspect/write the existing Finviz ledger; they do not look up credentials, send requests, retry, or authorize execution.

1. Run recovery-status. Retain its exact `receipt_reference` and `stop.run_id`.
2. For legacy state use migrate-ledger with those exact references, a unique `--release-id` (operation ID), `--operator CLAIM`, `--reason TEXT`, `--operator-decision allow-new-cycle`, and `--review-decision legacy-evidence-reviewed`. Migration preserves original raw bytes/base64/SHA256 and the entire current legacy record under a deterministic run ID. It retains a stop; it does not release it.
3. Run recovery-status again. Explicit release-rate-limit uses the current exact references and a NEW unique release-id plus operator/reason/allow-new-cycle. Known Retry-After must have elapsed. Unknown backoff requires `--review-decision unknown-quota-reviewed`; 401/403 require `auth-repair-intent-reviewed`. A migrated legacy stop requires `legacy-evidence-reviewed` (401/403 still require auth intent). Legacy review explicitly includes unresolved quota/attempt uncertainty. This is an operator claim, NOT authenticated identity, proven quota availability or credential repair. No credentials are read or changed.
4. Only a separately authorized `cycle --finviz-live` with a fresh run ID, existing finite budget/window and five-second minimum spacing can send. Old consumed claims and original run parameters remain immutable. A successful release does not itself run a cycle.

Operations share the capture root lock, preserve audited stop evidence, and bind operation IDs to immutable intent. Exact replay is a no-op; conflicting replay rejects. Replaying an old release cannot clear a later stop. Corrupt/ambiguous legacy state (including absent receipt, duplicate JSON keys, conflicting retained stop or invalid deadline) returns EVIDENCE_HOLD without deleting/resetting anything. Such evidence repair is outside this command.

Capacity remains finite: 64 capture runs, 128 operator operations, 1.5 MB readable ledger. Operator recovery returns CAPACITY_HOLD rather than rewriting an oversized ledger or pruning history. The existing capture may hit byte capacity before run capacity; no rotation/archival deletion or infinite-refresh claim. Release cannot make a full ledger reusable. Keep all evidence and obtain separately reviewed capacity handling.
